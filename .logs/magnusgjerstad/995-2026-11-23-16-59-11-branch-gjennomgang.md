### Oppgave
Gå gjennom branchene i repoet, se hva som ligger i dem, hvilke valg som må tas før de kan merges, om brukeren kan merge dem selv, og hva de neste stegene er.

### Plan
- `git fetch --prune`, sammenlignet hver branch med `origin/main` (commits, filer, merge-base).
- Prøvemerget parvis med `git merge-tree` for å finne konflikter.
- Leste arkitektur-spine, sprint-status og issues-filene til Christian og Magnus, og faglærers tilbakemelding på PRD-en.
- Sjekket rettigheter og branch protection med `gh`.

### Resultat
Lokal `main` var 2 commits bak og ble spolt fram til `origin/main` (a4ce499). Faglærer (Bård) har lagt til `tilbakemelding-prd.md` og `architecture/technology.md` (en beskrivelse av en annen app, FastAPI + Next.js, ment som referanse).

Branchene (alle bygger på a4ce499, ingen er bak main):
- `forslag-design-martin` (84 commits av MAGSKJ, logget under `.logs/magnusgjerstad/`): omarbeidet felles UX (ux-…-2026-11-11): DESIGN.md, EXPERIENCE.md, hull-analyse, wireframes og en klikkbar prototype (vanlig CSS), personvernerklæring, vilkår og opphavsrett. Endrer bare UX-mappa og Magnus' logger.
- `arkitektur-epics-christian` (18 commits): Christians egen UX (ux-…-2026-11-15-christian, Tailwind), arkitektur-spine (Django-monolitt, HTMX, Tailwind v4, SQLite, AD-1 til AD-22), epics (6 epics, 28 stories), review-rapporter og sprint-status. Alt ligger i egne mapper merket «christian».

Valgene som må tas er faglige, ikke tekniske: felles UX (gruppeversjonen eller Christians), om Christians arkitektur og epics skal være gruppens grunnlag, og hvilken rolle technology.md skal ha. Ingen filer endret utover denne loggen.
